# 프롬프트 패턴 — CHA Motion Kit 원문 분석

careerhackeralex.com/sharings/cha-motion-kit 카드의 프롬프트 원문을 분석한 결과. 이 스킬로 장면을 만들 때, 또는 사용자가 "다른 AI에 붙여 넣을 프롬프트"를 원할 때 이 구조를 따른다.

## 원문에서 뽑은 공통 규칙

1. **첫 문장 = 무엇을 + 기술 + 캔버스 + 길이**
   "…를 HTML+GSAP 모션그래픽으로 만들어줘. 캔버스 1080×830, 4.6초." (박자가 있으면 "128 BPM 박자에 맞춰")
2. **스타일은 한 줄로 고정**
   - 배경 짙은 차콜 `#0A0A0A`, 흰/회색 UI, 폰트 Geist(영문)·Pretendard(한글) 굵기 400–600.
   - **라임 `#D4F527`은 단 한 곳**(핵심 결과·마지막 형광펜·맨 위 카드 버튼 하나)에만.
   - 위쪽 두 모서리에 작은 회색 모노 라벨 (예: `"CHA · 128 BPM"`, `"03 THINGS"`, `"CHA · TOKEN BUCKET"`). 예시 수치라면 `"예시 값"`이라고 라벨에 명시.
3. **타임스탬프 비트 시트**
   "0–0.5초: …", "0.85초: …", "약 3.3초: …" 처럼 **초 단위로 상태 변화**를 나열. 각 비트에 무엇이 어디서 어떻게 움직이는지 한 줄씩.
4. **동작의 질감을 말로 지정**
   - 솟아오를 땐 빠르게 나와 부드럽게 감속(`expo.out`), 가라앉을 땐 살짝 가속(`in`)
   - 던질 때는 가속하며 빠지고, 앞으로 오는 카드는 살짝 튕기듯(스프링), 카메라는 부드럽게 감속
   - "끝까지 전체가 아주 천천히 위로 흐른다" — **멈추지 않는 미세 드리프트**로 정지 화면을 피함
   - "움직임은 끊기지 않게 이어지고" — 장면 내부 연속성
5. **읽는 시간 보장**: "마지막에는 CANVAS READY 상태를 0.8초 이상 읽게 해줘."
6. **인과관계**: "부드러운 커서와 인과관계가 분명한 동작", 선택한 **바로 그** 결과가 확장된다(그 카드가 전체 캔버스가 됨).
7. **결정론 · 탐색 가능**: "HTML/CSS와 일시 정지된 GSAP 타임라인 하나로 만들고 임의 시점 탐색이 가능하게." 시뮬레이션이면 "입력(요청 목록)을 고정해 두고 시간 t까지의 결과를 처음부터 다시 계산".
8. **정직성**: "제품 로고나 실제 앱의 성과 수치를 꾸며내지 말아줘." 기기 외곽(노트북·폰) 없이 화면 속 인터페이스만 보여 달라는 지시도 자주 등장.
9. **데이터로 개념 설명**: 토큰 버킷처럼 개념을 실제로 "돌려서" 보여 준다. 시나리오를 단계로 나누고 **단계마다 헤드라인이 바뀐다** (평소 → 몰림 → 거절 → 결론 공식).

10. **고급 결정론 기법을 구체적으로 지시** (리믹스·제너레이티브 원문):
    - "스프링은 닫힌 식 계단 응답으로, 목표가 바뀔 때마다 스프링 하나씩을 더해서 시간 t만의 함수가 되게"
    - "시뮬레이션은 처음에 480Hz 고정 간격으로 끝까지 한 번 계산해 저장하고, t의 프레임은 저장한 값을 읽어 그린다"
    - "t에서 반복(스텝) 횟수를 계산해 처음부터 다시 돌려 맞춘다" (반응-확산·점균)
    - "단어 폭은 measureText로 한 번만 재서 캐시, DOM을 건드리지 않고 캔버스에 직접"
    - "랜덤·타이머·onUpdate 없이"
11. **알고리즘·수치를 이름으로 못 박기**: Gray-Scott(f .0545, k .062), Jeff Jones 2010 Physarum(3×3 확산, 0.915 감쇠), Bayer 4×4, SDF smin, Catmull-Rom, 홀수 배음 13개. 모델이 "그럴듯한 흉내"가 아니라 실제 구현을 하게 만든다.
12. **수치를 라벨로 노출**: "GRAY–SCOTT · F .0545 · K .062", "40,000 AGENTS · NO MAP", "용량 10 · 초당 2개 충전 · 예시 값" — 화면이 기술적으로 정직해 보이고 설명 효과도 생긴다.
13. **강조색의 유일성 선언**: "라임은 공과 파문뿐", "라임은 두 스캔선뿐", "화면의 유일한 라임". 매 프롬프트 끝에 다시 한 번 못 박는다.
14. **현재 대상 강조**: "지금 막고 있는 링만 밝게, 나머지는 흐리게", "원 가까이 있는 단어는 한 단계 밝게".
15. **애니메이션 원리를 명명**: 스쿼시, 웅크림(예비동작), 스미어, 오니언 스킨 4개, 조금 지나쳤다가 제자리(오버슈트).
16. **마무리 문장**: 마지막 1–1.5초에 결론 한 줄("하나씩 뚫으면 됩니다", "지도 없이도 연결은 스스로 길을 찾습니다") + 완성 상태 유지.

## 프롬프트 템플릿 (붙여 넣기용)

```
{주제}를 {설명하는/보여 주는} 모션그래픽을 HTML+GSAP로 만들어줘. 캔버스 {1080×830}, {N}초{, BPM 박자에 맞춰}.
- 짙은 차콜 #0A0A0A 배경, 흰 글자는 Geist/Pretendard 굵기 600. 위쪽 두 모서리에 작은 회색 모노 라벨("{브랜드} · {주제}", "{보조 라벨}"). 라임 #D4F527은 {딱 한 곳}에만.
- {레이아웃: 왼쪽/가운데/아래에 무엇이 있는지}
- 0–{a}초: {첫 상태 → 등장}
- {b}초: {조작/원인}
- {c}초: {결과가 보이는 순간}
- {d}초부터: {결론 헤드라인} — {0.8}초 이상 읽게.
움직임은 끊기지 않게 이어지고, 등장은 빠르게 나와 부드럽게 감속(expo.out), 퇴장은 살짝 가속, 끝까지 전체가 아주 천천히 흐른다.
HTML/CSS와 일시 정지된 GSAP 타임라인 하나로 만들고 임의 시점 탐색이 가능하게 해줘. {시뮬레이션이면: 입력을 고정하고 t까지 처음부터 재계산.}
제품 로고나 실제 수치를 꾸며내지 말아줘.
```

## 확장 섹션 (prompt-motion.com 형식 — 긴 프롬프트)

복잡한 장면은 태그 블록으로 나눈다. 마지막 두 블록은 품질을 크게 좌우한다.

```
<brief> 무엇을, 누구에게, 어디에 쓰는지 </brief>
<canvas> 1080×830 · 30fps · N초 · 무음 </canvas>
<style> 팔레트 · 폰트 · 강조색 1곳 규칙 · 라벨 </style>
<beats> 초 단위 상태 리스트 </beats>
<build>
1. 비트 그리드를 먼저 정하고 상태 목록을 확정한다.
2. 하나의 paused 타임라인(또는 render(t))으로 만든다.
…
7. 전체 렌더 전에 비트마다 한 프레임씩 렌더한다. 그리드에서 벗어나거나, 비좁거나, 읽기 어려운 것을 고친다.
</build>
<gotchas>
카메라가 스케일하는 요소에 will-change를 넣지 않는다. 텍스트가 흐려진다.
모핑 컨테이너 안에서 바뀌는 텍스트는 자체 등장·퇴장 타이밍이 있어야 겹치지 않는다.
루프라면 마지막 프레임을 첫 프레임과 같게 — 커서 위치와 속도까지. 아니면 루프가 튄다.
</gotchas>
<start> 먼저 입력값을 물어보고, 코드를 쓰기 전에 비트 그리드 위의 상태 목록을 보여 줘. </start>
```

## 원문 예시 (요약 발췌) — 전문은 `prompt-library.md`

**타이포 · 바에서 솟아오르는 워드** — 4.7초 · 128 BPM
0–0.5초 가운데 두꺼운 흰 막대가 양옆으로 그어짐 → 0.5–1.4초 막대 윗변 뒤에서 "RESEARCH"가 마스크 안에서 솟고, 막대는 납작해져 단어 폭의 밑줄이 됨 → 두 박자마다 단어가 가라앉고 다음 단어("DRAFTS", "AUTOMATE")가 솟으며 밑줄 길이도 맞춰 변함 → 약 3.3초 아래로 한글 줄 "리서치 · 초안 · 반복 업무"가 떨어지고 라임 형광펜이 좌→우.

**트랜지션 · 카드 스택 스와이프** — 4.6초
3D로 비스듬히 쌓인 카드 3장(모노 라벨 "STEP 01 · 질문", 큰 제목, 설명, 알약 버튼, "01 / 03") → 0–0.85초 위에서 내려다본 원근으로 천천히 회전 → 0.85초 맨 위 카드가 비틀리며 오른쪽으로 던져지고 남은 카드가 스프링으로 한 칸 전진, 라임 버튼이 새 맨 위 카드로 이동 → 2.15초 두 번째 카드 왼쪽으로 → 1–2.8초 카메라가 정면으로 펴지며 마지막 카드 "이제 자동으로"가 정면에 자리 잡고 아주 천천히 커짐.

**화면 속 작업 · 명령 한 줄로 장면을 열다** — 6.5초
기기 외곽 없음. 프로젝트 목록 → 0.35초 명령 팔레트 열림 → 0.95초 "새 캔버스" 입력 → 2.2초 검색 결과 하나 선택 → 3.5초 선택한 그 카드가 전체 캔버스로 확장 → "CANVAS READY" 0.8초 이상.

**모션 용어 · 01 이징** — 6초
흰 원이 좌→우 이동, 0–2초 Linear / 2–4초 Ease-in / 4–6초 Ease-out, 구간마다 이징 이름을 하단에 크게, 원 뒤에 모션 트레일로 속도 차이를 보이게.

**리믹스 · 토큰 버킷 시뮬레이션** — 12초
왼쪽 10칸 통(라임 토큰, 맨 위 칸은 초당 2개로 반투명하게 차오름, 처리 시 토큰이 오른쪽으로 빠져 사라짐, 큰 숫자 "7 / 10 토큰") · 오른쪽 요청 기록(최신이 위로 미끄러져 들어옴, 거절은 흐리게 + 번호 취소선 + 빨간 "거절") · 아래 0–12초 토큰 그래프와 요청 눈금. 시나리오: 0.5–3초 초당 2번 → 3.3초부터 1.4초간 16번 몰림 → 4.9–8.6초 초당 4번(절반 거절) → 9초부터 0.9초 간격(회복). 단계마다 헤드라인: "평소엔 충전이 소비를 따라잡고" → "한꺼번에 몰리면 통이 바닥나고" → "빈 통이면 채워질 때까지 거절" → "한도 = 통의 크기 + 채워지는 속도".
